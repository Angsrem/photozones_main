# Task ID: 10 — Закрытая админ-панель (admin)

## Что реализовано

Полная закрытая админ-панель менеджера на светлой теме. Все страницы клиентские (`'use client'`), данные через `fetch` к готовым API в `/api/admin/*`. Public-layout НЕ применяется к `/admin` (route group `(public)` отдельно).

### Файлы
- `src/app/admin/_lib.ts` — shared client helpers: типы (`Lead`, `PhotoZone`, `Booking`, `DateBlock`, `Manager`), `api()` обёртка над fetch (с пробросом status/body ошибок), `phoneDigits`, `waLink`, `telLink`, `LEAD_STATUS_STYLES` (светлая палитра бейджей), `LEAD_STATUS_LABEL`, `CATEGORY_LABEL`, `BOOKING_STATUS_LABEL`.
- `src/app/admin/layout.tsx` — клиентский layout: проверка `/api/admin/me` при монтировании → редирект на `/admin/login` если 401 (кроме самой страницы логина). Светлая тема-обёртка `<div className="light min-h-screen bg-background text-foreground">`. Десктоп-сайдбар (256px) с навигацией (Дашборд/Заявки/Календарь/Фотозоны), `usePathname` для активного пункта. Шапка с аватаром+именем+email менеджера и кнопкой «Выйти» (DELETE `/api/admin/me`). Мобильная навигация через `Sheet` (side=left). Страница `/admin/login` рендерится без сайдбара.
- `src/app/admin/login/page.tsx` — центрированная форма входа (email + password) с PRE-заполненными демо-данными `admin@fotozona24.ru / admin123`. POST `/api/admin/login`, при успехе `router.replace('/admin')`. Прелоадер, тосты ошибок, ссылка «Вернуться на сайт».
- `src/app/admin/page.tsx` — дашборд:
  - 4 KPI-карточки (Всего заявок, Новые, Подтверждены, Конверсия %) с цветными иконками.
  - BarChart по статусам (recharts, цветные столбцы по статусам).
  - Список «По источникам» с прогресс-барами.
  - Список «Популярные фотозоны» с прогресс-барами.
  - Список «Последние 7 заявок» с бейджами статусов и ссылкой «Все → /admin/leads».
- `src/app/admin/leads/page.tsx` — таблица заявок:
  - Табы статусов (Все/Новые/Перезвонили/Подтверждены/Выполнены/Отказ).
  - Поиск по имени/телефону/комментарии (debounce 350мс).
  - Диапазон дат (`dateFrom`/`dateTo`).
  - Sticky-header таблица с колонками: Создана/Клиент/Телефон/Мероприятие/Фотозона/Источник/Статус.
  - Клик по строке → `Dialog` с деталями (`/api/admin/leads/[id]`): карточки клиента и мероприятия, кнопки **tel:** и **wa.me** (с автоподстановкой текста), источник, комментарий, список бронирований, форма смены статуса (Select) + выбора фотозоны (Select) + Textarea заметки, кнопка «Сохранить» (PATCH). При 409-конфликте — жёлто-красный alert и тост. При `CONFIRMED` без фотозоны — amber-предупреждение.
- `src/app/admin/calendar/page.tsx` — календарь занятости (МЕСЯЧНАЯ СЕТКА 6×7, Пн–Вс):
  - Переключатель месяца (←/→), кнопка «Сегодня».
  - Фильтр по фотозоне (Select).
  - Каждая ячейка: число (выходные — красные), цветные точки-чипы бронирований (цвет стабилен по id фотозоны, до 2 в ячейке + счётчик `+N`), блокировки с иконкой `Ban`, счётчики `●N` (брони) и `∞N` (заявки).
  - Клик по дню → `Dialog` с деталями: бронирования (с кнопкой удалить), блокировки (с кнопкой разблокировать), заявки (с tel/wa), форма блокировки даты (POST `/api/admin/bookings` type=block с выбором фотозоны/причины), форма добавления брони (POST type=booking с проверкой занятости).
  - Панель «Свободные аналоги»: при выборе занятой фотозоны (Select) — запрос `?alternativesFor=`, выдача до 5 карточек с превью-изображением, бейджем «свободна», ценой и категорией.
- `src/app/admin/photozones/page.tsx` — CRUD фотозон:
  - Поиск + таблица (превью/название+slug/категория/цена/бейдж/хит/статус/кол-во элементов/действия).
  - Кнопка «Добавить» → `Dialog` с формой: title, slug (автоген из title, ручная правка), description, category (Select), occasions (Checkbox-чипы), basePrice, sizeW/sizeH, sortOrder, images (Textarea по строкам), includes (Textarea по строкам), badge (Select HIT/NEW/—), hit (Switch), isActive (Switch), элементы (name+price с добавлением). Сохранение POST (создание) или PATCH (редактирование).
  - Удаление через `AlertDialog` с подтверждением (DELETE `/api/admin/photozones/[id]`).
  - Подсказка: элементы добавляются после создания фотозоны (нужен её id).

### Исправления в существующем API
- `src/app/api/admin/stats/route.ts`: в `db.lead.groupBy` для `photozoneId` и `source` добавлены явные `_count` и `orderBy` (без них Prisma падала с `P2019: Missing fields: id` из-за дефолтной сортировки по `id`, которого нет в `by`). Без этого фикса дашборд падал с 500.

### Тестирование
- `bun run lint` — проходит без ошибок.
- `GET /admin/login`, `/admin`, `/admin/leads`, `/admin/calendar`, `/admin/photozones` — все отдают 200.
- API с авторизованной сессией: `/api/admin/login` (POST), `/api/admin/me` (GET), `/api/admin/stats`, `/api/admin/leads`, `/api/admin/calendar?month=`, `/api/admin/calendar?date=`, `/api/admin/calendar?date=&alternativesFor=`, `/api/admin/photozones` — все 200, возвращают корректные данные.
- Демо-доступ подтверждён: `admin@fotozona24.ru / admin123` → менеджер «Анна Менеджер» (role: ADMIN).

## Что не успел / известные проблемы
1. **Элементы фотозоны**: при создании новой фотозоны элементы не сохраняются одновременно (нужно сначала создать фотозону, потом открыть повторно и добавить элементы). Это ограничение существующего API `POST /api/admin/photozones` — он не принимает `elements` в payload. Чтобы это исправить, понадобилось бы расширить API; в задании сказано «не создавай новые API», поэтому оставил как есть с подсказкой в UI.
2. **PATCH photozones**: аналогично не передаёт `elements` (только основные поля). Удаление/добавление элементов через UI пока не реализовано — нет соответствующего эндпоинта.
3. **Recharts в светлой теме**: цвета графиков зашиты вручную (oklch-значения), что нормально для светлой темы, но неtheme-aware. Для админки это ок.
4. **Календарь**: цвет точек фотозон детерминирован из хеша id, но не настраивается пользователем. Это компромисс — иначе пришлось бы делать маппинг «фотозона → цвет» в отдельном хранилище.
5. **Пагинация заявок**: API отдаёт до 200 заявок; пагинация на клиенте не сделана (только скролл с `max-h-[70vh] overflow-y-auto`). Для демо-объёма (7 заявок) достаточно.
6. **Dev-сервер**: во время тестов системный `bun run dev` несколько раз останавливался; запускал вручную через `setsid bun run dev` для проверки. Системный авто-рестарт может не сработать — при превью стоит убедиться, что dev-сервер активен.

## Важные детали для следующих агентов
- Светлая тема достигается обёрткой `<div className="light ...">` в `admin/layout.tsx` и `admin/login/page.tsx`. Переменные из `.light` в `globals.css` подхватываются всеми `bg-background`, `text-foreground`, `card`, `primary` и т.д.
- `_lib.ts` — приватный файл (импортируется из страниц как `./_lib` для `admin/page.tsx` и `../_lib` для вложенных страниц `admin/leads/page.tsx` и т.п.).
- Авторизация — httpOnly cookie, ставится `/api/admin/login`. `credentials: 'include'` в `api()` обязательно.
- Префикс `_` в имени файла `_lib.ts` НЕ делает его приватным для импортов — это работает только для папок. Импорт проходит нормально.
