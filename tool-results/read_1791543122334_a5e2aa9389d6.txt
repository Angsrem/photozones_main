  1451→  1451→### 1. SSR Middleware для /admin (`src/middleware.ts`, Edge runtime)
  1452→  1452→
  1453→  1453→Раньше защита /admin была только клиентской: `AdminLayout` (use client) делал `GET /api/admin/me`, и при 401 делал router.replace('/admin/login'). Это позволяло атакующему перехватить HTML-ответ через отключённый JS или curl, увидеть структуру админки до проверки.
  1454→  1454→
  1455→  1455→Теперь middleware валидирует cookie `fz_admin_token` (формат `body.sig`, HMAC-SHA256) на уровне сервера ДО рендера страницы. Если токен невалидный/просрочен/отсутствует — `NextResponse.redirect('/admin/login')`. `/admin/login` пропускается без проверки.
  1456→  1456→
  1457→  1457→ВАЖНО: Next.js middleware работает в **Edge runtime**, НЕ может импортировать из `src/lib/auth.ts` (там Node.js `crypto`, `next/headers.cookies()`). Поэтому:
  1458→  1458→- Секрет-резолвер продублирован (та же логика fallback, что в `auth.ts:resolveSecret()` — в prod требует `ADMIN_JWT_SECRET` ≥32 символа, в dev/sandbox использует `dev-secret-fotozona24-krsk-sandbox-fallback-32-chars-min`).
  1459→  1459→- HMAC-SHA256 через Web Crypto API (`crypto.subtle.importKey` + `crypto.subtle.sign`), без Node.js `createHmac`.
  1460→  1460→- Base64url через `btoa/atob` + `TextEncoder/TextDecoder` (Edge-safe, без `Buffer.from('…','base64url')`).
  1461→  1461→- Constant-time string compare своей реализацией (Edge не имеет `crypto.timingSafeEqual`).
  1462→  1462→- `exp` проверяется из распарсенного JSON-тела токена.
  1463→  1463→
  1464→  1464→Matcher: `['/admin/:path*']` — срабатывает на `/admin` и `/admin/**`. Middleware-логика сама фильтрует `/admin/login` (early `NextResponse.next()`).
  1465→  1465→
  1466→  1466→Замечание: Next.js 16.1 выводит deprecation-warning «The "middleware" file convention is deprecated. Please use "proxy" instead» — middleware.ts всё ещё работает полностью, но в будущем возможно потребуется переименование в `proxy.ts`. Не делал, т.к. task явно требовал `src/middleware.ts`.

  1468→  1468→### 2. 2FA TOTP для админа (`src/lib/totp.ts` + схема + API + UI)
  1469→  1469→
  1470→  1470→#### Схема (`prisma/schema.prisma`)
  1471→  1471→- В `Manager` добавлено поле `totpSecret String?` — base32-секрет (RFC 4648), null = 2FA выключена.

  1474→  1474→#### TOTP-библиотека (`src/lib/totp.ts`, Node.js `crypto`, не Edge)
  1475→  1475→- `generateSecret()` — 20 случайных байт → base32 (32 символа, ~160 бит энтропии).
  1476→  1476→- `generateCode(secret, atTimeMs?)` — RFC 6238: counter = `floor(time/30)`, 8-byte big-endian, HMAC-SHA1(base32decode(secret), counter), dynamic truncation, mod 10^6, 6-значная строка с ведущими нулями.
  1477→  1477→- `verifyCode(secret, code, atTimeMs?)` — проверяет код в текущем окне ±1 (3 валидных кода: prev/cur/next), constant-time `timingSafeEqual`.
  1478→  1478→- `otpAuthUrl(secret, email)` — `otpauth://totp/Fotozona24:email?secret=…&issuer=Fotozona24&digits=6&period=30` для QR-кода (если будет QR-библиотека; пока без неё — пользователь может вставить секрет вручную в приложение-аутентификатор).
